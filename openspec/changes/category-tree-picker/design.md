# Design

## Context

见 `proposal.md`；行为契约见 `specs/ledger-taxonomy/spec.md`。

现状约束：

- `categories.parent_id` 已存在且限定两级，`categories_page` 已能加子分类、删除时做迁移保护。
- `quick_entry_sheet` 的分类区是「4 列 × N 行」的一级网格，选中二级时用 `_highlightCategory` 把高亮落到父级。
- 识别提示词的分类候选来自硬编码的 `kCategoryKeywords`（6 组）。
- `AutoCreatePolicy` 已实现配额（单笔 1、7 天 3、总数 40、开关），但只在交互面板保存时用。
- 后台自动入账（`AutoScreenshotSaver` / `CaptureEntrySaver`）只做名字匹配，不建分类。

## Goals / Non-Goals

**Goals:**

- 让用户在面板里能选到二级分类，并能就地新增一级/二级分类。
- 模型能看见账本的真实分类（含自建、含二级），从而大幅减少落到「其他」。
- 缺分类时按配额自动补，且前后台口径一致。

**Non-Goals:**

- 不支持三级及更深的层级。
- 不改 `categories` 表结构，不做迁移。
- 不做分类的批量重排 / 拖拽（现有排序能力不变）。

## Decisions

### D1 面板两段式，而不是「一行一级 + 抽屉」

布局：一级横排（4 列网格不变）→ 选中一级后，下方出现该一级的二级区（横向可滚动的小胶囊 + 「新增」）。

**理由**：参考的成熟形态就是这样，一级不换行、二级只占一条，面板高度可控；「一行一级 + 展开抽屉」会在分类多时把面板撑得很高。

**备选（否决）**：点击一级弹二级弹层 —— 多一次模态跳转，取消路径变长。

### D2 没有二级的一级，点一下即选中

只有当该一级存在子分类时才展开二级区。**理由**：`其他` 这类分类本来就没有子项，强制「展开再选」等于多一次点击。

### D3 新增入口分两级，二级自动继承父级

一级区的「新增」建一级分类；二级区的「新增」以当前选中一级为 `parentId` 建二级。沿用现有 `CategoryRepository.ensure` 与面板的「保存时才落库」策略（`newCategoryName` 候选），取消记账不留空分类。

### D4 提示词用真实分类树，二级名带父级注释

`_categoryChoices()` 改为接收分类列表，输出形如：

```
出行交通（打车、公共交通、停车费）/ 购物消费（网购）/ 日用品 / 其他
```

二级只在括号里列名字，一级名始终保留。**理由**：模型选二级时能同时写出父级语义，减少把「打车」误解成一级分类的情况。

### D5 识别结果按「二级 → 一级」两级匹配

`matchCategory` 已经遍历全部分类（含二级），保持现实现；只把提示词换成真实分类树即可。若模型返回的是二级名，落库就是二级 id，统计按父级汇总由既有 `category-drilldown` 负责。

### D6 后台自动建分类复用同一配额，开关沿用「自动新建分类」

`AutoScreenshotSaver` 在匹配不到分类时：读 `autoCreateCategories` 开关 → `AutoCreatePolicy.checkCategory` → 允许则 `CategoryRepository.ensure` 并把这次创建记入配额日志；不允许则走既有兜底。

**理由**：用户只在一处看到「自动新建分类」这个开关，前后台必须同一口径，否则后台悄悄多建分类会让人困惑。

**待定**：后台新建的分类挂在一级还是直接做一级。倾向直接做一级（模型给的通常是「订阅服务」这种独立名），实现时若发现落一级会破坏统计再调整。

## Risks / Trade-offs

- [面板变高，小屏挤压] → 二级区固定单行、横向滚动，整个分类区维持现有的最大高度约束（222）与滚动。
- [模型乱造分类] → 配额挡住量；且只有「账本里不存在」的名字才会新建，已有名字走匹配。
- [二级分类让统计碎片化] → 统计始终按一级汇总，二级只在明细与下钻里出现。
- [后台建分类与用户在面板里改名冲突] → 都用 `ensure`（同名复用），不产生重复分类。

## Migration Plan

无数据库迁移。旧数据不受影响；已存在的一级分类不需要补子分类。
