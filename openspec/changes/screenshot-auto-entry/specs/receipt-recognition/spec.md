# Spec Delta

## MODIFIED Requirements

### Requirement: 选图后 SHALL 尝试识别

用户添加图片、或系统检测到截屏后，系统 SHALL 尝试用视觉模型识别图中文字，并在有结果时按结果预填金额、分类、标签、账户、备注与日期；MUST NOT 直接创建交易，保存仍由用户点完成。

MUST NOT 使用设备本地 OCR。仅当用户显式开启视觉识别并保存了 API Key 时，系统 SHALL 调用其配置的视觉模型；未开启、未保存 Key 或平台不支持时，系统 MUST NOT 发起任何识别请求、也 MUST NOT 上传图片，仅在用户添加图片后提示去设置里配置。

#### Scenario: 认出一张小票

- **WHEN** 用户已开启视觉识别并保存了 API Key，添加一张写着「合计 ¥44.50」「金豆餐厅 消费小票」的截图
- **THEN** 系统把图片发送给配置的视觉模型，面板金额变成 44.50、分类预选「餐饮」、标签填入候选、备注填入商家名，且用户可以改

#### Scenario: 检测到截屏后识别

- **WHEN** 视觉识别已启用，系统检测到一张小票截屏
- **THEN** 不打开面板也先完成识别，用户点开结果时直接看到预填内容

#### Scenario: 没配置时不识别、不上传

- **WHEN** 用户没有开启视觉识别（或没有保存 API Key），添加一张小票图
- **THEN** 不发起任何网络请求，面板提示「视觉识别未开启，可在设置里配置」，其它功能正常

#### Scenario: 已经有输入时不覆盖

- **WHEN** 用户已经填了金额 30 又加了一张图
- **THEN** 金额保持 30，识别只填空白字段（分类/标签/备注）

#### Scenario: 认不出金额

- **WHEN** 图片里没有可识别的金额
- **THEN** 面板给出「没认出金额，手动填一下」的提示，其它输入不变

## ADDED Requirements

### Requirement: 识别 SHALL 匹配分类、标签与账户

识别结果落到面板时，分类 SHALL 先做名称归一化（去空格/标点/全半角）与别名匹配，命中同收支类型的已有分类则直接预选；未命中时 SHALL 仅展示「将新建」候选，等用户保存时再按分类创建规则落库。

标签 SHALL 从固定词表生成，单笔最多 2 个，同名/近似名复用，创建时机与分类相同；账户 SHALL 只匹配已有账户的名称或别名，匹配不到时沿用上次使用的账户，MUST NOT 自动创建账户。

#### Scenario: 别名命中已有分类

- **WHEN** 识别文本含「咖啡店」，本地已有分类「餐饮」
- **THEN** 面板预选「餐饮」，不新建分类

#### Scenario: 分类不存在

- **WHEN** 识别出「咖啡」，本地没有同名或别名分类，且用户开启了自动新建
- **THEN** 面板显示「将新建分类：咖啡」；用户点保存后才创建，取消则什么也不留下

#### Scenario: 自动打标签

- **WHEN** 识别文本含「微信支付」与「咖啡」，本地已有标签「微信支付」
- **THEN** 面板复用「微信支付」标签，并按词表补充最多一个候选标签，总数不超过 2 个

#### Scenario: 账户只匹配不新建

- **WHEN** 识别文本含「招行储蓄卡」，本地没有同名账户
- **THEN** 面板沿用上次账户，不新建账户，也不改变用户已选账户
