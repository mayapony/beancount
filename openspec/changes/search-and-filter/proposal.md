# Proposal

## Why

明细只能一个月一个月翻：想找「上个月那笔 236 的超市采购」或者「所有带出差标签的支出」，只能逐月滚动肉眼找。
导入 48 笔真账之后这个问题就已经存在，账目攒到几百笔时它就是「数据进去了但找不回来」。

## What Changes

- **搜索页**：明细页标题栏新增放大镜入口，打开独立搜索页；输入关键词即时匹配备注、分类名、账户名与标签名。
- **结构化筛选**：类型（全部/支出/收入）、时间范围（本月/近三个月/今年/全部），以及「更多筛选」里的分类、账户、标签、金额区间。
- **筛选摘要**：已生效的筛选以胶囊展示，可单个移除；一键清空。
- **结果复用明细的排版**：按日分组、显示分类图标与金额、点行进交易详情、缩略图可看大图。
- **空结果**：「没有匹配的账目」，并保留筛选条件让用户改。
- 非目标：保存搜索条件、跨账本搜索、模糊纠错、按金额排序、导出搜索结果。

## Capabilities

### New Capabilities

- `ledger-search`: 在本地账本里按关键词与结构化条件检索交易，并展示可继续操作的结果列表

### Modified Capabilities

（无：明细页的按月浏览行为不变，搜索是独立入口。）

## Impact

- `lib/data/repositories/transaction_repository.dart`：新增 `LedgerFilter` 与 `searchLedger()`；查询先用 SQL 收敛（类型/时间/分类/账户/金额），关键词在内存里匹配备注与关联名称
- 新增 `lib/pages/search_page.dart`
- `lib/pages/transactions_page.dart`：标题栏加搜索入口；把日分组列表抽成可复用 widget（搜索页也用它）
- 新增 `lib/widgets/ledger_day_list.dart`（从明细页抽出的日分组渲染）
- 测试：仓储筛选组合、搜索页交互、设备端回归
- 无新增依赖
