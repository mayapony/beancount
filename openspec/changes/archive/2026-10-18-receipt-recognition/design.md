# Design

## 两层：识别（重）与解析（轻）

```
图片 bytes
   ↓  ReceiptRecognizer（接口）
   │   ├─ MlKitReceiptRecognizer  ← Android/iOS，离线，中文模型
   │   └─ NoopReceiptRecognizer   ← Web/桌面/测试
   ↓ 纯文本
ReceiptParser（纯 Dart）
   ↓ ReceiptGuess{amountCents?, categoryName?, note?, happenedAt?, rawText}
   预填面板 → 用户确认 → 保存
```

把"认字"和"理解"分开的原因：解析器可以拿真实 OCR 噪声文本做单元测试（不依赖设备），
换模型时解析器不用动；反过来调解析规则也不需要在真机上跑。

## 解析规则（尽量确定）

1. **金额**：先找含 `合计|总计|实付|应付|金额|total` 的行 → 取该行最大的金额；找不到再取全文最大金额。
   金额正则同时接受 `¥ 38.50`、`￥38.50`、`38.50元`、`38.50`。
2. **日期**：`YYYY-MM-DD` / `YYYY/MM/DD` / `YYYY年M月D日` / `MM-DD`（补当年）；找不到就用当前时间。
3. **分类**：关键字表（见 spec）。命中多个时按"更长更具体"优先（餐厅 > 餐）。
4. **备注**：取第一行里最长的一串非数字文本（通常是店名），去掉「消费小票」「小票」等尾巴。
5. **置信度**：认出金额 = high，只有分类 = low，什么都没有 = none。

## 面板交互

选图落定后（`_images` 追加成功）：

- 若金额为空（`_amount == '0'`）→ 自动跑识别；
- 识别中：金额行显示「识别中…」小字（不遮挡输入）；
- 有结果：填金额（按当前账户币种语义，金额是面板里的数字）、选分类（若未选）、填备注（若为空）、改时间（若识别到日期）；
- 无结果：一句「没认出金额，手动填一下」；
- 抛错：一句「识别失败」，其它不变。

用户已有的输入一律不覆盖——识别是"补空"，不是"改写"。

## 平台与依赖

- `google_mlkit_text_recognition` + Android `text-recognition-chinese`（中文模型）；识别完全在设备上。
- 条件导入：`receipt_recognizer.dart` 里 `import 'package:flutter/foundation.dart'` 判断 `kIsWeb`，
  Web 侧返回 `NoopReceiptRecognizer`，避免插件通道在 Web 上崩。
- 首次识别可能慢（模型加载），所以放在后台执行，不阻塞面板。

## 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 是否直接入账 | 否，预填待确认 | 识别有错，钱不能自动记 |
| 金额取哪个 | 合计行 > 最大金额 | 小票小计很多，合计才是这一笔 |
| 识别失败 | 降级为手动 | 不能因为模型没装就不能记账 |
| 解析器与识别器分离 | 是 | 解析可用噪声文本单测，换模型不改 |
| Web | 空实现 | 插件只有移动端 |

## 风险

| 风险 | 应对 |
|---|---|
| 中文模型没打进 APK | `build.gradle` 显式依赖 `text-recognition-chinese`（少了会 ClassNotFound，已踩过） |
| OCR 噪声（如「牛内面」） | 解析只依赖数字与关键字，不依赖字完美 |
| 首次识别慢 | 后台执行 + 「识别中…」，用户可先打字 |
| 识别出外币金额 | 仍按面板当前币种语义记录，汇率逻辑不变 |
| APK 变大 | 中文模型约数 MB，随 release 一并给出体积 |
