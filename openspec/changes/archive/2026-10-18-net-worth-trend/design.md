# Design

## 不落快照表

净资产 = Σ 账户初始余额 + Σ 收入 − Σ 支出（截至某一时点）。转账在两个账户间等额抵消，对全局净值没有影响。

所以「历史净值」不需要快照：把当前账本按月份累计一遍就是精确值。

这比快照表好的地方：

| | 快照表 | 推导 |
|---|---|---|
| 改账/删账 | 需要回填所有后续快照，否则曲线与账户余额对不上 | 自动一致 |
| 补记循环交易 | 同上 | 自动一致 |
| 迁移 | 新表 + 回填脚本 | 无 |
| 口径 | 两套（快照 vs 实时）容易分叉 | 一套 |

## 数据结构

```dart
enum NetWorthRange { sixMonths, thisYear, all }

class NetWorthPoint { final DateTime at; final String label; final int cents; }

class NetWorthSeries {
  final List<NetWorthPoint> points;
  int get current;        // 最后一个点
  int get startValue;     // 第一个点
  int get changeCents;    // current - startValue
  bool get isEmpty;       // 没有任何交易
}
```

`NetWorthRepository.load({range, now})`：

1. `initialSum` = `SELECT SUM(initial_balance_cents) FROM accounts`；
2. 读全部交易（只需要 `type / amount_cents / happened_at`）；
3. 按 `yyyy-MM` 分桶累加 `+income − expense`（转账跳过）；
4. 按范围生成月份序列，逐月累加，得到每个月的月末净值；
5. 「全部时间」从最早一笔所在月开始，不早于它。

`watch({range})` 复用 `tableUpdates()` 流：改一笔账，曲线立刻重画。


- 用 fl_chart 的 `LineChart`，样式沿用洞察页的趋势图（金色主线 + 渐变填充、无网格竖线）。
- 轴线只保留横轴月份；纵轴不标数字（净值绝对值不如图形趋势重要）。
- 空状态：「还没有足够的数据」+ 一句提示，不画假曲线。

## 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 是否存快照 | 不存，纯推导 | 单一真相，改账自动一致（见上表） |
| 粒度 | 按月 | 与「看这个季度怎么样」的心智一致；按日留给以后 |
| 转账处理 | 排除 | 全局抵消，计入会重复 |
| 初始余额计入时间 | 视为"起点之前" | 它是账户的期初，不属于任何一个月 |
| 纵轴刻度 | 不显示 | 净值绝对值意义不大，形状与变化额更重要 |

## 风险

| 风险 | 应对 |
|---|---|
| 初始余额被算成某个月的收入 | 计入 `initialSum` 基线上，不进任何月的增量；用例覆盖 |
| 净值可能为负，图表越界 | 纵轴 minY 允许负数，曲线按数据 min/max 自适应 |
| 空账本画出 0 线 | `isEmpty` 时直接空状态 |
| 大量交易时每次重算 | 单人账本万级以内；按需再加缓存或 SQL 聚合 |
