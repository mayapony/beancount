# Proposal

## Why

金豆目前记一笔始终需要一个「用户记得去记」的动作：要么手动打开 App 录入，要么手动加图让视觉模型识别后预填（M7 只做到这一步，截屏自动触发未做）。支付完成到入账之间隔着的这一步，导致漏记成为常态。

市面同类 App 靠「无障碍抓屏 + 通知监听」在支付发生的那一刻就自动入账。这套方案对通用产品有两个硬障碍——Google Play 明令禁止非无障碍用途使用无障碍 API、以及把「能读全屏」的权限交给他人带来的隐私与合规负担。而本项目是**单人自用、Android 侧载、不上架、本地优先**，恰好绕开了这两个障碍，是把「自动记账」落地的合理时点。

## What Changes

- 新增「自动记账」能力：支付发生时，通过无障碍抓屏与通知监听自动提取金额、方向，直接入账并弹通知，用户事后据通知与实际消费核对。
- 提取失败时的自愈兜底：用户截图 → 当次直接入账（视觉模型）+ 留证（包名 / 页面指纹 / 控件树快照）→ AI 生成该页面的提取规则 → 之后同一页面自动入账，不再需要截图。
- 事后审计而非事前确认：入账后弹通知，并提供「最近自动记账」列表供核对、修改、删除。
- 候选合并去重：同一笔支付被通知 / 页面 / 截图多条路径捕获时，按「包名 + 金额 + ±120s」合并，避免重复入账。
- 规则质量门槛：新规则入库时静默回放验证（正例解出真值、负例沉默），验证不过则标待定、不进自动。

## Capabilities

### New Capabilities

- `auto-entry`: 支付发生后自动捕获并记入账本，涵盖无障碍/通知/截屏三类采集、自愈提取规则、事后通知审计与候选去重。

## Impact

- 新增 Android 无障碍服务与通知监听服务（`AccessibilityService` / `NotificationListenerService`），需在 `AndroidManifest.xml` 注册并声明 `BIND_ACCESSIBILITY_SERVICE`、`BIND_NOTIFICATION_LISTENER_SERVICE` 等权限；该能力 Android-only，iOS / Web 不提示、不报错。
- 复用现有视觉识别接口（`lib/services/ocr/ReceiptRecognizer` + `parseReceiptText`）与写入路径（`lib/services/entry/EntryWriter` / `TransactionRepository`）。
- 新增「最近自动记账」列表与候选合并逻辑；现有 `lib/data/dedupe.dart` 的去重键语义只覆盖「同一份数据导入两次」的幂等，不匹配多源实时捕获，需新增候选级合并去重。
- 新增持久化：提取规则文件、捕获候选、自动记账审计列表。
- 隐私约束：界面采集与规则存储在本地完成；规则生成走用户配置的云端模型（上传脱敏控件树快照），截图兜底识别走视觉模型——两者均为「配置后上传」的显式例外，沿袭 `receipt-recognition` 约定。
