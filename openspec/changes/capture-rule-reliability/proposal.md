# Proposal

## Why

真机排查（2026-11-07，红米 25113PN0EC / Android 17）确认：截图识别的金额、商户、时间基本准确，但**从截图学出的规则几乎全部停在 `pending`**，导致自动记账除页面级灰度规则外从不生效。五条规则里四条被判死，原因是规则生成与执行的两处语义过宽，外加一处入账来源标记缺失。

本文档先把真机证据记下来，作为修复输入；具体实现等测评结束再补 design 与 tasks。

## 真机证据

| 应用 / 页面 | 识别结果 | 入账 | 规则结果 |
|---|---|---|---|
| 支付宝 账单详情（¥2.50 武汉可多） | 金额、商户、时间、分类「购物」、账户「支付宝」全对 | ✅ | `pending`（排除词「积分」命中页面「立即领取6积分」） |
| 淘宝 订单详情（¥36.9 实付款） | 正确选了实付 36.9，未误取商品总价 39.9；时间为空 | ✅ | `pending`（正则 `¥\s*(\d+)` 首个命中 39.9 ≠ 36.9） |
| 小米商城 订单详情（¥4199） | 金额正确 | ✅ | `pending`（排除词「券」命中页面下方「券｜下单享8.7折」） |
| 小米商城 订单列表（¥299） | 金额正确 | ✅ | `grey` 成功命中，二次进入自动入账 |
| 微信 账单详情（¥11.90） | 金额、商户、时间全对 | 去重命中未重复记 | `pending`（通知规则，见问题 3） |

## 问题清单

### 问题 1：排除词对整页文本匹配，促销文案把规则判死

`CaptureRuleExecutor.apply` 用 `rule.excludeKeywords.any(source.contains)`，`source` 是**整页平铺文本**。页脚任意一句「领积分」「券」「退款」都会让整笔判定为「不是支付」，规则回放验证随即失败并永久留在 `pending`。

- 证据：支付宝页含「立即领取6积分」→ 规则 `exclude=[余额,优惠,积分,奖励]` → `verified=false`；淘宝页含「退款宝」→ 同样 `false`。
- 影响：4/5 条规则因此从未生效，这也是「自动记账一次都没成功」的直接原因之一。

### 问题 2：生成的正则不锚定金额语义，取页面第一个 ¥ 数字

淘宝订单详情同时有 ¥39.9（商品总价）与 ¥36.9（实付款）。模型生成 `¥\s*([0-9]+(?:\.[0-9]{1,2})?)`，执行时 `firstMatch` 命中 39.9，与真值 3690 不符 → 验证失败。

- 模型对图像的判断是对的（识别出 36.9），错在规则只表达「任意 ¥ 数字」，没有表达「实付/实付款/交易成功 附近」。

### 问题 3：通知规则用「最近一条该包通知」生成，可能与支付无关

截图后学习时取 `lastNotification(package)`，拿到的是「最近一条该应用的通知」。微信场景下抓到的是一条聊天消息（「马淑慧」），模型据此生成了裸正则 `(\d+(?:\.\d+)?)`。

- 本次因聊天文本无数字而验证失败，属侥幸。若某条含数字的聊天通知恰好通过验证，**此后任何带数字的微信通知都会被记一笔账**。

### 问题 4：截图自动入账未标 `source: auto`，不进审计列表

`lib/services/screenshot/auto_entry.dart` 调 `EntryWriter.submit` 时未传 `source`，默认成「手动」。后果：

- 「最近自动记账」里看不到截图记的账（支付宝 ¥2.50、淘宝 ¥36.9、小米商城 ¥4199 都只在明细里）；
- 用户以为自动记账没执行，实际是没被标记。

### 问题 5：两大主力应用的控件树读不出，无障碍路径对它们无效

- 微信：`dumpTree lines=1`（树完全空），已在学习时正确标记为「截图优先」。
- 支付宝：110 个节点仅 186 字符文本，金额读不到；但仍生成了无障碍规则并停在 `pending`，属于无效尝试。
- 小米商城：187 节点 / 1164 字符，无障碍可读，这是唯一跑通自动入账的应用。

### 问题 6：抓帧时机早于页面渲染完成，指纹不稳定

同一页面 1 秒内抓两帧：46 节点 `a59f75a7` → 64 节点 `53a1908f`。当前 300ms 去抖后直接取帧，页面仍在变化时算出的指纹与后续稳定态不一致。

## What Changes

（待补）方向：排除词只看金额邻域、规则锚定金额语义、通知规则必须用真实支付通知验证、截图入账标记来源、对树不可读的包不再生成无障碍规则、抓帧等待页面稳定。
