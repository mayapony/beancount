# 金豆 Bean Count · 产品计划

> 本文档贯穿产品整个生命周期，是唯一的顶层路线图。实现被拆分为若干里程碑（Milestone），
> **每个里程碑对应一份 PRD**，由产品侧撰写；PRD 通过 OpenSpec 的 change 提案落地为代码。

---

## 1. 产品概述

| 项 | 内容 |
|---|---|
| 中文名 | 金豆 |
| 英文名 | Bean Count |
| 寓意 | 一颗圆豆子 / 小种子，肚子里存金币，「种豆得钱」 |
| 定位 | 本地优先、极简的个人记账 App |
| 一句话 | 打开就记，截图就记，四个 Tab 装下全部财务 |

**核心体验**：明细（记账与查看）、洞察（图表分析）、资产（账户与净资产）、设置；
截图记账为**截屏后自动触发**的隐性能力（不占 Tab）。

## 2. 背景与动机

从 BeeCount 项目中做了「剃刀」，砍掉云同步、多人共享、桌面小组件、内购、4 语言等大量功能后，
重新实现一个**完全归自己掌控**、按个人使用习惯定制的最小记账 App。

关键取舍：**本地单机优先**，不做账号体系与云同步；但架构上为「未来支持 S3 同步」预留空间。

## 3. 目标用户与场景

- **用户**：开发者本人（单一用户，无多人协作）。
- **场景**：
  1. 日常随手记一笔（手动）。
  2. 截图/拍照支付账单 → AI 自动识别入账。
  3. 月底看趋势与分类占比。
  4. 查看账户余额、净资产、信用卡还款日。
  5. 换设备时导入/导出数据（CSV/Excel）。

## 4. 设计原则（非功能约束）

1. **本地优先**：数据全部在本地（SQLite），不上传任何第三方。
2. **极简**：四个 Tab，没有多余的入口；能一步完成的不做两步。
3. **可迁移**：数据必须能导入导出，不把用户锁死。
4. **可扩展**：数据模型用 UUID + 软删除 + 时间戳，为未来 S3 同步预留。
5. **隐私**：无遥测、无广告、无账号。

## 5. 范围（Scope）

### 5.1 In Scope（保留）

- **记账核心**：记一笔（收入/支出/转账）、多账本、账户体系、二级分类、明细列表、搜索筛选。
- **自动化**：循环交易（房租/工资等定期）、备注历史记忆、分类迁移合并。
- **洞察**：收支趋势折线、分类占比/排行、净资产/资产构成。
- **资产**：账户列表+余额、净资产走势、信用卡还款提醒、多币种+汇率换算。
- **AI 记账**：**截屏后自动识别** → 确认 → 入账（不设常驻入口）；单供应商可插拔。
- **数据迁移**：导入（CSV/Excel/支付宝/微信账单）、导出（CSV/Excel）。
- **安全与个性化**：应用锁（PIN/生物识别）、主题（亮/暗/跟随系统）。

### 5.2 Out of Scope（砍掉）

预算、标签、日历视图、年度报告、交易附件、头部皮肤、字体字号、多语言 i18n、桌面小组件、
应用内自更新、捐赠/内购、分享海报、营销卡片、账号登录/2FA、多人共享账本、欢迎引导页。

### 5.3 Backlog（未来，不阻塞当前）

S3 云同步、预算、标签、多语言（中英）、桌面小组件、语音记账、AI 对话助手。

## 6. 技术基线

| 项 | 选型 |
|---|---|
| 框架 | Flutter（3.27.x / Dart 3.6.x） |
| 状态管理 | Riverpod |
| 数据库 | drift + sqlite（本地） |
| 路由 | go_router（4 Tab 用 StatefulShellRoute） |
| 图表 | fl_chart |
| AI 视觉 | Qwen-VL / GLM-4V 等，做成可插拔 Provider |
| 依赖源 | 国内镜像 `pub.flutter-io.cn` |
| 研发规范 | OpenSpec（spec-driven）+ TDD（测试先行） |

**数据模型关键决策**：主键一律 `UUID 字符串`；每表带 `createdAt / updatedAt / deletedAt`（软删除）；
账户余额由「期初 + 交易求和」计算得出，不落库 —— 全部为未来 S3 同步而设计。

## 9. PRD 与 OpenSpec 工作流

一份 PRD 的落地流程：

1. **写 PRD**（`docs/prd/M{编号}-{名称}.md`）：目标、用户故事、验收标准、范围。
2. **开 change 提案**：`openspec propose` 生成 `openspec/changes/<id>/`（proposal + tasks + spec 增量）。
3. **任务拆分**：change 内的 `tasks.md` 拆成 ≤2 小时的原子任务。
4. **TDD 实现**：每个任务先写失败测试 → 实现 → 变绿。
5. **归档**：`openspec archive <id>`，spec 增量合入 `openspec/specs/`，成为「真相」。

**提交规范**：`<type>(<scope>): <中文描述>`，type ∈ feat/fix/refactor/test/docs/chore。
示例：`feat(transaction): 支持收支转账三合一录入`。

## 10. 设计语言（已定稿）

由 **UI UX Pro Max**（https://uupm.cc/）推导，落地为 [`docs/DESIGN.md`](DESIGN.md) 与 `lib/theme/tokens.dart`：

## 11. 风险与开放问题

| 风险/问题 | 影响 | 应对 |
|---|---|---|
| 截图识别的准确率 | AI 记账体验 | 永远让用户确认/编辑后再入账；识别失败兜底为手动 |
| 视觉模型成本 | 每次识别调用 | 选性价比模型（Qwen-VL）；单张压缩后上传 |
| 未来 S3 同步的架构债 | 迁移成本 | 从第一天用 UUID+软删除，控制后续成本 |
| 数据丢失 | 用户信任 | 内置导出（M8）+ 后续 S3 同步兜底 |
| 单人维护 | 速度 | 极简范围 + OpenSpec 控制复杂度 |
| 「多账本」在 §5.1 范围内但未实现 | 计划与代码不一致 | 决定单独立项，或从 §5.1 移除 |
| 截屏自动触发与视觉模型未接 | M7 只完成本地 OCR 预填 | 需要时立项：监听截屏 / 可插拔视觉 Provider |
| 生物识别未接 | 应用锁目前只有 PIN | 按需补 local_auth，或把 §5.1 改成仅 PIN |

## 12. 里程碑总览（一页速览）

- **M0 奠基** → **M1 数据** → **M2 账户/分类** → **M3 记账** → **M4 自动化** / **M5 洞察** / **M6 资产** / **M7 AI** → **M8 导入导出** → **M9 安全** → **M10 发布**
- 每条线互不阻塞：M4/M5/M7/M9 都依赖 M3，但彼此可并行。

## 13. 发版方式

- **自动发布**：推送 `v*` tag（如 `v1.0.2`）→ GitHub Actions 跑 analyze + test → 用仓库 Secrets 还原 keystore → 构建 release APK → 校验不是 debug 签名 → 创建 GitHub Release（APK + `SHA256SUMS.txt`）。versionName 取 tag，versionCode 取 run number。
- **手动演练**：Actions → Release → Run workflow，只上传 workflow artifact，不建 Release。
- **本机出包**：`tools/build_release.ps1`，仅供自己安装，不发布。
- 密钥不入库（`android/key.properties`、`*.jks`、`*.keystore` 均在 `.gitignore`）；步骤与排查见 [`RELEASING.md`](../RELEASING.md)。
- 暂不支持：Google Play / App Store 上架、iOS 打包、AAB、增量更新。
